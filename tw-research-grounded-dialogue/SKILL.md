# 接地氣迭代對話引擎 v1.0
## STORM-Inspired Grounded Research Dialogue

## 核心哲學

「**好問題比好答案更重要。**
STORM 的核心發現是：直接叫 LLM 提問，問出來的問題很平庸。
但若先確立「誰在問」「為什麼問」，問題品質會質變。
本工具模擬 5 個帶著立場的研究者，用真實文獻來問你——這才是真正的學術壓力測試。」

> 設計靈感：Stanford STORM（2024, Shao et al., NAACL）
> 核心機制：ConvSimulator（多角色對話）+ Co-STORM Moderator（盲區注入）

## Step 1：情境接收確認卡

```
╔══════════════ 接地氣迭代對話引擎啟動 ══════════════╗
📌 任務：多視角 × 引用錨定的迭代研究對話
🎯 靈感來源：Stanford STORM 研究方法論
⚠️  原則：每個答案必須有 WebSearch 依據，禁止推測性聲明

請確認以下三項資訊：
1. 研究主題（一句話）
2. 當前階段
   A. 發想期——還在找研究方向
   B. 文獻期——已有文獻，想深化理解
   C. 寫作期——有草稿，想驗證論點接地性
3. 這次對話的核心問題或焦點（可以模糊）
╚═══════════════════════════════════════════════════╝
```

若由其他 skill 自動呼叫，上述三項由呼叫方傳入，略過詢問直接執行。

## Step 2：視角選擇（Persona Generation）

根據研究主題與階段，從 `references/persona-templates.md` 選取 3-5 個最適合的研究者視角：

| 視角代號 | 角色定義 | 核心提問風格 |
|---------|---------|------------|
| 🔴 SKEPTIC | 懷疑論者 | 挑戰假設、質疑因果、要求證據 |
| 🔵 METHOD | 方法論專家 | 質問設計缺陷、效度威脅、樣本問題 |
| 🟢 PRACTITIONER | 實務應用者 | 問「這有什麼用？」「在教室裡能做什麼？」|
| 🟠 BRIDGE | 跨領域闖入者 | 引入不相關領域的類比與概念 |
| 🟣 LOCAL | 台灣本土脈絡 | 問台灣情況、在地研究、文化差異 |

輸出視角選擇說明：
```
本次啟用視角：[視角1] + [視角2] + [視角3]（+ 可選視角4/5）
選擇理由：[一句話說明為何選這幾個視角最有價值]
```

## Step 3：迭代接地對話（核心迴圈）

每輪對話依以下結構執行：

### 對話格式

```
━━━ 第 [N] 輪｜視角：[視角名稱] ━━━

❓ [視角名稱] 的問題：
「[基於該視角立場提出的尖銳問題，具體指向研究的某個面向]」

🔍 WebSearch 搜尋策略：
搜尋語：「[具體搜尋字串1]」「[搜尋字串2]」

📚 搜尋結果摘要：
[1] [來源名稱/作者年份]：[核心發現 1-2 句]
[2] [來源名稱/作者年份]：[核心發現 1-2 句]
[3] [來源名稱/作者年份]：[核心發現 1-2 句]

💬 接地氣回答：
根據 [1]，[回答內容]。然而 [2] 卻指出，[對比觀點]。
在台灣脈絡下，[3] 的研究顯示 [在地發現]。

🔶 未使用片段（盲區候選）：
• [片段描述]——來自 [3] 但未被引用
• [片段描述]——來自搜尋但與主問題偏離

📍 本輪收穫：[一句話總結這輪對話的核心發現]
```

### 迴圈規則

- **輪數**：發想期 3 輪；文獻期 3-4 輪；寫作期 2-3 輪
- **每輪換視角**：確保多元覆蓋
- **引用格式**：行內 [1][2] 錨定，不可使用無來源聲明
- **停止條件**：
  - 達到輪數上限
  - 使用者說「夠了」「停」
  - 連續兩輪未發現新觀點（收斂信號）

## Step 4：盲區注入（Moderator 機制）

每輪結束後，執行盲區掃描：

```
🎯 主持人盲區注入：

已搜尋但未被任何視角引用的資訊片段：
• [片段 1]（來源：[引用]）
• [片段 2]（來源：[引用]）

注入問題：
「你的研究有沒有考慮到 [未引用片段的核心觀點]？
 這可能意味著 [潛在影響]——你的立場是？」
```

此問題自動作為下一輪的起始問題，由任一視角接手回答。

## Step 5：階段性輸出（依呼叫階段切換格式）

根據 Step 1 確認的階段，輸出對應格式（詳見 `references/dialogue-formats.md`）：

### 發想期輸出

```
╔════════════ 接地氣探索地圖 ════════════╗
對話輪數：[N] 輪｜啟用視角：[列表]

■ 經質問後存活的研究方向：

方向 A：[標題]
  核心問題：___
  已有文獻支撐：[1][2]
  待解決的質疑：[SKEPTIC 提出的問題]
  可行性評估：高 / 中 / 低

方向 B：[標題]
  ...

■ 最強方向推薦：[方向X]
  推薦理由：[一句話，說明此方向最能抵抗質疑]

■ 下一步建議：使用 tw-research-proposal-diamond Phase 2 繼續聚焦
╚═════════════════════════════════════════╝
```

### 文獻期輸出

```
╔════════════ 深化缺口分析報告 ════════════╗
對話輪數：[N] 輪｜啟用視角：[列表]

■ 現有文獻的盲點（質問後發現）：
  缺口 1：[描述] [1][2]
  缺口 2：[描述] [3]

■ 方法論潛在威脅：
  [METHOD 視角發現的設計問題]

■ 本土化挑戰：
  [LOCAL 視角的台灣脈絡問題]

■ 跨領域啟發：
  [BRIDGE 視角引入的新概念]

■ 研究定位建議：
  「本研究填補了___缺口，在___脈絡中，透過___方法...」

■ 下一步建議：使用 tw-research-methodology-designer 確認方法論選擇
╚═════════════════════════════════════════╝
```

### 寫作期輸出

```
╔════════════ 論點接地性驗證報告 ════════════╗
對話輪數：[N] 輪｜檢驗論點數：[N]

■ 引用接地狀況：
  ✅ 有文獻支撐的論點（[N] 個）：
     • [論點摘要] → 引用：[1][2]
  
  ⚠️ 懸空論點（需補充引用）（[N] 個）：
     • [論點摘要] → 建議搜尋：「[關鍵詞]」
  
  ❌ 過度推論（無法找到文獻支撐）（[N] 個）：
     • [論點摘要] → 建議：降低主張強度或刪除

■ 引用多元性：
  [來源語言/地區分布，是否過度依賴單一來源]

■ 修改優先序：❌ 先處理 → ⚠️ 次之 → ✅ 確認即可

■ 下一步建議：返回 tw-research-writing-coach 進行段落改寫
╚═════════════════════════════════════════╝
```

## 降級方案

| 情況 | 處理方式 |
|------|---------|
| WebSearch 無結果 | 標注「[搜尋無結果]」，跳過此輪引用，改為提出「待查問題清單」|
| 主題過於模糊 | 先啟動 SKEPTIC 視角問一輪「你的研究問題是什麼？」協助聚焦 |
| 使用者已有文獻清單 | 優先用使用者提供的文獻錨定，WebSearch 作為補充 |
| 輪數不夠（想繼續）| 詢問「要加開第 [N+1] 輪嗎？建議聚焦在 [未解決的盲區]」|
